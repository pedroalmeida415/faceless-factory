# Server-Owned Workflow Runtime

Accepted. Workflow node execution is owned by the server, where the runtime state machine and durable transitions are persisted in the database; the frontend is a projection for authoring, inspection, and control rather than the source of execution truth. The runtime tracks branch-level readiness through Tasks: each Branch executes as one Task, each Task owns one or more AI Generation Operations for its Batch Items, and downstream Tasks can wait on upstream branch outputs until their dependencies are satisfied. Dependency wake-up uses a transactional wake-up-call model: when a Task reaches a terminal state, the runtime checks dependent task dependencies and resumes satisfied dependents in the same transaction. Shared business rules and transport contracts should be locked down before independently implementing the backend runtime and frontend projection; Storybook and frontend tests should then mock server projection responses plus SSE events that report granular state-machine changes, instead of modeling a local fake execution runtime or rereading the entire state machine for every minor batch-item update.
