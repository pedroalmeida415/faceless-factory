# JSONB Workflow Graph

Accepted. The workflow graph definition is persisted on the user-owned workflow row as a JSONB `graph` Workflow Graph containing authored graph structure, React Flow-compatible node and edge fields, node positions, input values, and node config, and it can be loaded quickly as the Workflow Graph Projection before hydrating the Workflow Execution Projection from durable runtime state. Material graph changes are debounced into saves of the current workflow graph, including changes to disconnected nodes so authored work is not lost, while text input edits save only on blur to avoid keystroke-level persistence. Persisted graph revision history is intentionally not modeled; undo and redo history is client-local and ephemeral unless persistent history becomes a product feature. Ephemeral view preferences such as output display mode stay in client state so they do not trigger graph saves. This deliberately favors fast frontend graph hydration and flexible node-editor iteration over prematurely normalizing every node, edge, socket, and UI-position detail into relational tables or mapping React Flow objects into a separate persisted graph shape; execution state remains separately persisted by the server-owned runtime.
